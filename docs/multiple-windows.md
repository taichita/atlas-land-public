# 複数ウィンドウ

- `Ctrl+N` または「メニュー → 新しいウィンドウ」で追加します。デスクトップのAtlasをもう一度起動しても別ウィンドウが開きます。
- 「メニュー → 2画面に配置」で、左右のモニターに1ウィンドウずつ、各2ペインで配置します。既に開いている余分なペインのタブは同じウィンドウの2つ目のペインへ集めます。
- 会話・成果物・Webログインは共通です。タブ、会話の入力下書き、ペイン配置はウィンドウごとに保存します。
- Webのログイン時にはWebView2標準のパスワード保存・更新確認を利用できます。保存した資格情報と入力候補はBrowsingプロファイルを共有するウィンドウで利用できます。Chromeからの自動取り込みは行いません。サイト自身がログインの有効期限を切った場合には再ログインが必要です。
- 一方を閉じても、ほかのウィンドウとバックエンドは動き続けます。最後のウィンドウを閉じると終了します。ローカルAIが実行中の場合は従来通り通知領域に残ります。
- ウィンドウ数と位置も保存し、次回起動で復元します。モニターが外れていたら画面内に戻します。

実行ホストは単一プロセスのApplicationContextで複数Formを管理し、Nodeバックエンドは1つだけ起動します。同じWebView2ユーザーデータフォルダとBrowsingプロファイルを利用します。追加起動は名前付きイベントで既存プロセスへ通知します。

タブ・UI状態は `workspace.json` の `windows.main` / `windows.window-2` 等に保存します。既存データはmainへ初回にコピーし、旧トップレベルの値も互換用に保持します。ウィンドウ位置は同じアプリ保存先の `windows.json` に保存します。

検証: `node test/multi-window-e2e.mjs`。個人データやAIを使わない2ウィンドウのUI検証で、タブ・下書き・配置の分離、再読み込み、片方の終了、4→2ペインのタブ保持を確認します。ネイティブ版は `ATLAS_PROFILE` と `AI_WORKSPACE_DATA` で検証用保存先を分離できます。
