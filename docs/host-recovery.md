# 画面だけが終了した場合の復旧

## バックエンド停止からの復旧（0.4.1）

画面が残ったまま裏側のサーバーが終了した場合も、その終了を検知して復旧します。同じローカル接続先で再起動するため、画面・Webタブ・編集中の入力を読み直しません。復旧後に会話状態と利用量を更新し、通信が止まっている間は利用量を「未更新」と表示します。短時間に停止が続く場合は自動復旧を止め、上部の「再接続」から再試行できます。

Codexの利用上限はAIの送信・応答に関するエラーとして表示し、Web閲覧やファイル編集を止めません。失敗したAIの指示を自動で再送しません。公式仕様：[App Serverのエラー](https://learn.chatgpt.com/docs/app-server#errors)。サーバーが終了した際は、データ保存先の `service-lifecycle.log` にシグナルや終了理由を記録します。

検証：`test/backend-recovery.ps1` は隔離したサーバーを停止し、同じ接続先への復旧と画面を読み直さないことを確認します。`node test/service-recovery-e2e.mjs` は利用上限を模した送信拒否、通信停止中の下書き編集、復旧後の保存、指示の再送がないこと、メモの継続利用を確認します。これらの試験は実際のAIには依頼しません。

Atlasの画面プロセスが終了しても、AIを動かすバックエンドが残る場合があります。Atlasを開き直すと、同じバックエンドへ再接続し、保存されているウィンドウとタブを表示します。新しいバックエンドを重ねて起動せず、進行中の処理と下書きを維持します。

接続先はアプリのローカル保存領域の `backend-session.json` に記録します。プロセスIDだけでなく、開始日時、実行ファイル、アプリの場所を照合し、127.0.0.1の認証付き応答を確認してから再接続します。生きている接続先が応答しない場合は、二重起動せず「画面を復元」からの再試行を案内します。このファイルにはローカル接続の秘密値が含まれるため、配布・公開・ログ出力の対象にしません。

通常終了でバックエンドも終了した場合は、従来どおり空の1ウィンドウで起動します。自動再起動の常駐プログラムは追加していません。

検証：`powershell -NoProfile -ExecutionPolicy Bypass -File test/host-reattach.ps1`。隔離プロファイルで画面プロセスだけを停止し、バックエンドのPID維持、再接続、UI表示、未送信の下書き保持、認証に失敗しても二重起動しないことを確認します。AIへの指示は送信しません。

2026-09-22の事象では、画面プロセスが不在でバックエンドが残っており、通常終了・例外のログとWindowsのアプリケーションエラー記録は確認できませんでした。終了を引き起こした原因自体は未特定です。この修正はその原因を断定して解消するものではなく、残った処理に安全に再接続できるようにするものです。
